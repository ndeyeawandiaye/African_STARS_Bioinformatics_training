Sequencing, file formats and assembly strategies

Bridge talk — module 1

Two ways to build a genome from Illumina reads

Both start with the same raw material (FASTQ files) and the same first steps (quality control, trimming, contamination check). They differ in how the genome is rebuilt:

  • De novo assembly: reads are stitched together without any reference (new or very divergent virus, bacteria).
  • Mapping (reference-based): reads are aligned to a known genome, then a consensus is called (known virus: SARS-CoV-2, Rift Valley fever, dengue…).

Pipeline 1 — de novo assembly (Illumina)

Step Tool What it does Main output
1 FastQC per-base quality, adapters, GC content, duplication html
2 trimmomatic trims adapters and low-quality ends, drops short reads fastq.gz
3 FastQC + MultiQC same check after trimming; MultiQC merges all samples in one page html
4 Kraken2 +BLAST assigns each read to a taxon (virus, human, bacteria…); needs a database txt
5 SPAdes builds contigs ( --meta for metagenomes) fasta
6 QUAST assembly statistics, comparison to a reference if you give one html

Optional additions: seqkit stats (quick read counts), Prokka / Bakta (gene annotation for bacteria), KrakenTools (keep only the reads of the target virus before assembling).

Pipeline 2 — mapping to a reference (Illumina)

ImportantSteps you do NOT repeat

If you already ran pipeline 1 on the same samples, steps 1 to 3 are already done (FastQC, trimmomatic, MultiQC, Kraken2). Reuse the trimmed reads in results/trimmed/. Only the steps in white below are new.

Step Tool What it does Main output
1–4 FastQC, trimmomatic, MultiQC, Kraken2 already done (see pipeline 1) fastq.gz
5 bwa (or minimap2) aligns each read to the reference SAM
6 samtools sorts, indexes and counts mapped reads bam, .bai
7 samtools flagstat / depth / coverage how many reads cover each position txt
8 ivar consensus majority base at each position; N where depth is too low FASTA
9 freebayes / bcftools calls SNPs and small indels VCF
10 awk / seqkit / summary table decide if the genome is good enough csv
11 Pangolin or Nextclade, MAFFT, IQ-TREE lineage and phylogeny (modules 2–3) tree

Sequencing technologies

Illumina (short reads) Oxford Nanopore (long reads)
Read length typically 50–300 bp from hundreds of bp to tens of kb
Accuracy very high per base lower per read, improving with chemistry and basecalling
Output paired-end reads (R1 + R2) single long reads, available in real time
Strengths accurate SNPs, high throughput structural variation, repeats, portable devices, fast turnaround
Typical weakness repeats and structural variants errors in homopolymers, need for polishing

Library preparation approaches (viruses)

WGS / metagenomics Amplicon (e.g. ARTIC)
Principle sequence everything in the sample amplify the virus in overlapping tiles (multiplex PCR)
Best when you do not know what you are looking for routine viral surveillance (the most common approach)
Watch out for most reads may not come from the virus amplicon dropout when primer sites mutate

A FASTQ record

@read_name
ACGTACGT...            sequence
+
IIIIHHHHGGGG...        quality, one character per base

Phred score Q = −10·log10(P error): Q20 → 1 error in 100, Q30 → 1 in 1,000. The character encodes Q + 33.

Mapping or de novo assembly?

Mapping to a reference De novo assembly Hybrid
Principle align reads to a known genome rebuild the genome without reference combine short and long reads
Tools bwa, minimap2, iVar, bcftools SPAdes, MEGAHIT; Flye, Canu Unicycler
Choose when known, little-divergent virus; amplicon data new/divergent pathogen, bacteria, rearrangements both read types available

Three questions to decide: Do I have a good reference? Are my reads long? Is my coverage sufficient?

Pitfalls to remember

  • Cross-contamination and barcode bleed between samples (always read the negative control).
  • Wrong reference or unsuitable lineage.
