1. BCL to FASTQ and sample sheets

A NovaSeq run does not produce FASTQ files directly. The instrument writes BCL files (base calls with quality scores) plus run metadata. A conversion step then creates FASTQ files:

NovaSeq run → BCL files + run metadata → BCL Convert → per-sample FASTQ files

BCL Convert performs the base-call conversion and demultiplexing: it separates reads by sample using the index sequences. The mapping from index to sample comes from the sample sheet.

The sample sheet

SampleSheet.csv tells the software which index combination belongs to which sample. A minimal, simplified example:

[Header]
FileFormatVersion,2

[BCLConvert_Data]
Lane,Sample_ID,Index,Index2
1,Sample_A,ATTACTCG,TATAGCCT
1,Sample_B,TCCGGAGA,ATAGAGGC

The exact sections and column names depend on the software version. Check the BCL Convert documentation for the version you use.

Installing BCL Convert

BCL Convert is distributed by Illumina and runs on Linux (64-bit) only. It is not available through apt, conda or pip. Typical steps:

  1. Download the installer from the Illumina support site here (BCL Convert Software page, a free Illumina account is required). The file is an RPM package, for example bcl-convert-4.x.x-x.el7.x86_64.rpm.
  2. Install it (administrator rights needed):
sudo rpm -i bcl-convert-4.x.x-x.el7.x86_64.rpm
  1. Check that it works:
bcl-convert --version
bcl-convert --help

On Debian/Ubuntu, rpm is not the native package manager. Use alien or ask your system administrator. On a shared HPC cluster, BCL Convert is often already installed as a module (module avail bcl), so check before installing anything.

Note

BCL Convert needs a lot of memory and CPU cores for a full NovaSeq run. Check the system requirements for your version in the Illumina documentation before running it.

Running BCL Convert on the command line

The basic command needs three things: the run folder, the sample sheet, and an output folder.

bcl-convert \
  --bcl-input-directory /path/to/run_folder \
  --sample-sheet /path/to/SampleSheet.csv \
  --output-directory /path/to/fastq_output

Useful options:

Option Purpose
--force Overwrite an existing output directory
--no-lane-splitting true Merge reads from all lanes into one FASTQ per sample
--bcl-sampleproject-subdirectories true Write FASTQ files in one subfolder per project
--first-tile-only true Convert only the first tile, for a quick test
--bcl-num-conversion-threads, --bcl-num-compression-threads, --bcl-num-decompression-threads Control CPU usage

A quick test before a full conversion:

bcl-convert \
  --bcl-input-directory /path/to/run_folder \
  --sample-sheet SampleSheet.csv \
  --output-directory test_output \
  --first-tile-only true \
  --force

Checking the output

After a successful run, the output directory contains:

  • the per-sample files Sample_A_S1_R1_001.fastq.gz and Sample_A_S1_R2_001.fastq.gz
  • Undetermined_S0_R1_001.fastq.gz and Undetermined_S0_R2_001.fastq.gz for unassigned reads
  • a Reports/ folder with Demux_Metrics.csv (reads per sample) and Top_Unknown_Barcodes.csv (most frequent unassigned indexes)
  • a Logs/ folder with the run log

If the Undetermined file is very large, the usual causes are a wrong index in the sample sheet or a wrong index orientation (for example Index2 given as the reverse complement). Top_Unknown_Barcodes.csv helps to diagnose this.

2. The case

TipCase summary (based on public cell-line documentation)

A 43-year-old woman was diagnosed with triple-negative ductal breast carcinoma (stage I, grade 3). Her mother also had breast cancer, raising the question of a possible inherited predisposition.

Two cell lines were established from this patient: HCC1395, derived from her breast tumour, and HCC1395BL, derived from her blood and established as a normal lymphoblastoid cell line. Both have been widely used in biomedical research, and sequencing data are publicly available.

In this case study, we will focus on the matched normal sample, HCC1395BL, to investigate germline variation.

The central question: Could this woman carry an inherited pathogenic variant in a breast cancer susceptibility gene, and what evidence would be needed to assess its potential significance for her and her relatives?

Our goal is to identify and prioritise candidate variants using sequencing quality control, variant calling, annotation and interpretation. This is a research exercise, not a clinical diagnosis or a clinical classification of any variant.

The data used in the case study

Item Value
SRA run SRR37849526 (experiment SRX32714296, study PRJNA1445230)
Sample HCC1395BL_normal_WES: whole exome of the normal (blood-derived) cell line of a breast cancer patient
Capture NimbleGen Exome v3 (hybrid selection)
Platform Illumina HiSeq 2500, paired-end
Size about 77.7 million read pairs, 15.5 Gb of bases

Since the normal sample is used to look for inherited (germline) variants, we start with its reads.

3. Download sequencing data from NCBI SRA

Méthode A — Download sequencing data using the NCBI SRA Toolkit

The Sequence Read Archive (SRA) hosted by NCBI stores raw sequencing data. We can download a sequencing run using prefetch from the SRA Toolkit and convert it into FASTQ files using fasterq-dump.

In this example, we use run SRR37849526.

a. Create a directory for the data

Create a directory named SRA inside your Documents folder:

mkdir -p ~/SRA
  • mkdir creates a directory.
  • -p creates any missing parent directories and avoids an error if the directory already exists.
  • ~ represents the user’s home directory.

b. Download the SRA run

prefetch SRR37849526 --output-directory ~/SRA
  • prefetch downloads sequencing data from NCBI.
  • SRR37849526 is the SRA run accession.
  • --output-directory specifies where the downloaded data will be stored.

The expected file location is:

~/SRA/SRR37849526/SRR37849526.sra

c. Convert SRA to FASTQ

Once the download is complete, convert the SRA file into FASTQ format:

fasterq-dump ~/SRA/SRR37849526/SRR37849526.sra \
  --split-files \
  --outdir ~/SRA
  • fasterq-dump converts SRA data into FASTQ format.
  • --split-files writes paired-end reads into separate files, usually _1.fastq and _2.fastq. Single-end runs generally produce one FASTQ file.
  • --outdir specifies the output directory.

d. Check the output files

ls -lh ~/SRA/

For a paired-end run, the output may contain:

SRR37849526_1.fastq
SRR37849526_2.fastq

These FASTQ files can then be used for quality control, read alignment, and downstream genomic analyses.

Important: fasterq-dump may require substantial temporary disk space. Ensure sufficient free space before conversion. The commands above assume that the SRA Toolkit is installed and available in your terminal.

e. Compress the FASTQ files

FASTQ files can be large. Compressing them with gzip reduces disk space and makes them easier to store and transfer.

gzip ~/SRA/SRR37849526_1.fastq
gzip ~/SRA/SRR37849526_2.fastq

After compression, the files will be named:

SRR37849526_1.fastq.gz
SRR37849526_2.fastq.gz

Important: gzip replaces each original .fastq file with a .fastq.gz file by default. If you want to preserve the original files, use gzip -k instead.

To compress all FASTQ files in the directory:

gzip ~/SRA/*.fastq

To check the resulting files:

ls -lh ~/SRA/*.fastq.gz

f. Rename FASTQ files

Some sequencing workflows expect FASTQ files to follow a specific naming convention. For example:

SampleName_S1_L001_R1_001.fastq.gz
SampleName_S1_L001_R2_001.fastq.gz

The filename components mean:

  • SampleName: sample identifier.
  • S1: sample number in the sample sheet.
  • L001: sequencing lane 1.
  • R1: Read 1; R2: Read 2.
  • 001: file/chunk number.

For our downloaded SRA run, we can rename the compressed paired-end FASTQ files as follows:

cd ~/SRA

mv SRR37849526_1.fastq.gz SRR37849526_S1_L001_R1_001.fastq.gz
mv SRR37849526_2.fastq.gz SRR37849526_S1_L001_R2_001.fastq.gz

Check the resulting filenames:

ls -lh *.fastq.gz

Expected output:

SRR37849526_S1_L001_R1_001.fastq.gz
SRR37849526_S1_L001_R2_001.fastq.gz

Important: This is a naming example, not proof that the run came from NA12878. Use the actual sample identity and metadata associated with the SRA accession. The lane and chunk labels are also conventions; do not assume that an SRA run necessarily corresponds to a single Illumina lane or chunk.

Renaming files does not convert single-end reads into paired-end reads or change the read data. Confirm the run layout before using the _R1_ and _R2_ naming convention.

Method B — Import sequencing data using BaseSpace SRA Import

BaseSpace SRA Import is a BaseSpace Labs application that allows users to import sequencing data using an NCBI Sequence Read Archive (SRA) accession. This approach can simplify data preparation by avoiding the need to download an SRA file manually and convert it into FASTQ using the SRA Toolkit.

In this example, we use the SRA run accession SRR37849526.

Important: BaseSpace SRA Import is a BaseSpace Labs application. Its availability, behavior, output format, and support may differ from those of standard Illumina applications. Verify the generated outputs before using them in downstream analyses.

a. Open the SRA Import application

  1. Sign in to your BaseSpace account.
  2. Open the SRA Import application from BaseSpace Labs.
  3. Review the application description and disclaimer before proceeding.

BaseSpace Labs applications are provided as is. The application disclaimer states that Illumina does not undertake to provide technical support for this app and disclaims liability for its use.

b. Select the input data method

The application offers two input options:

  • Biosamples — Launch with FASTQs across multiple sequencing runs: use this option when the input consists of FASTQ data associated with biosamples across multiple sequencing runs.
  • Samples — Launch with FASTQs from a single sequencing run: use this option when working with FASTQ data from a single sequencing run.

For this example, start with Samples, since the input is one SRA run accession. If the application requires a different selection for importing the accession, follow the option descriptions and instructions displayed in the current interface.

c. Configure the analysis

Complete the required fields in the application.

Field Example value Purpose
Analysis Name SRR37849526_SRA_Import Identifies the import analysis.
SRA Accession SRR37849526 Specifies the NCBI SRA run to import.
Save Results To African_STARS_Training Specifies the BaseSpace project where results will be saved.

Enter the accession without a URL or filename extension.

Before launching the analysis, confirm that the accession is correct and that the selected destination project is appropriate.

d. Review the BaseSpace Labs disclaimer

Before launching the application, read the disclaimer and acknowledge it only if you agree to its terms.

The disclaimer explains that:

  • SRA Import is a BaseSpace Labs application.
  • The application is provided without a warranty.
  • Illumina is not obligated to provide technical support for the app.
  • The user accepts the stated limitations and risks associated with its use.

e. Launch the import

After completing the required fields and accepting the disclaimer, launch the analysis.

Monitor the analysis status until it finishes. If the application reports an error, inspect its status and available logs before attempting another import.

The application is expected to retrieve data associated with the specified SRA accession. The exact outputs and their organization depend on the application’s implementation and version.

Download the exome BED file

A BED file defines genomic intervals, such as the regions targeted by an exome capture kit. These intervals can be used to calculate coverage over the targeted regions.

Create a directory for reference files:

mkdir -p ~/SRA/reference

Download the BED file:

wget -P ~/SRA/reference \
  https://aml31.genome.wustl.edu/NimbleGen_v3_Exome.hg19.bed

The expected file path is:

~/SRA/reference/NimbleGen_v3_Exome.hg19.bed

Here: - wget downloads a file from a URL. - -P specifies the destination directory. - NimbleGen_v3_Exome.hg19.bed describes exome target intervals associated with the hg19 reference assembly.

Check that the file was downloaded:

ls -lh ~/SRA/reference/NimbleGen_v3_Exome.hg19.bed
head ~/SRA/reference/NimbleGen_v3_Exome.hg19.bed

Use the BED file for coverage analysis

In BaseSpace QC Coverage Metrics, select the downloaded BED file as the target regions file, provided that it matches the capture kit and reference assembly used for the sample.

Important compatibility check: the filename indicates that the BED uses hg19 coordinates. Use it only if the alignment BAM is compatible with hg19/GRCh37 and the target intervals match the exome assay. Do not use it directly with an hg38/GRCh38 alignment.

The BED file defines where coverage is measured; the BAM file contains the aligned sequencing reads used to calculate that coverage.

4.Uploading a dataset to BaseSpace

BaseSpace Sequence Hub allows you to upload sequencing data generated outside the platform, such as FASTQ files produced by a local bioinformatics pipeline. You can upload data through the web interface or use the BaseSpace Command-Line Interface (CLI) for larger datasets. Illumina: Uploading FASTQ files.

a. Upload from the web interface

  1. Create a free account at BaseSpace Sequence Hub and sign in.
  2. Open an existing project where you have write access, or create a project.
  3. Open the project and select File → Upload → Files.
  4. Select the file type, such as FASTQ.
  5. Select or create the sample or biosample associated with the data, and provide the required library information.
  6. Select Finish Upload and wait for the transfer to complete.

The web uploader supports files up to 250 GB per file and up to 16 files per upload, according to Illumina’s BaseSpace CLI guidance. For larger transfers, use the CLI. Upload documentation.

b. Upload FASTQ files using the CLI

The BaseSpace CLI (bs) is useful when uploading many FASTQ files or transferring large datasets.

Step 1 — Install the CLI

Download the version for your operating system from the official BaseSpace CLI documentation.

Step 2 — Authenticate

bs auth

Follow the authentication instructions displayed by the CLI.

Step 3 — Identify your project

bs list projects

Alternatively, obtain the project ID from the project URL in your browser.

Step 4 — Upload FASTQ files

Suppose the FASTQ files are stored in ./data/fastq/. Upload them to an existing project:

bs dataset upload \
  -p <PROJECT_ID> \
  --recursive ./data/fastq/

Replace <PROJECT_ID> with the actual project ID.

The CLI defaults to FASTQ uploads. The files must satisfy BaseSpace’s FASTQ naming and content requirements. Official upload instructions.

c. Upload a complete sequencing run

If you want to upload an entire instrument run, including its BCL files and run metadata, use the run-upload command rather than the FASTQ dataset-upload command.

For example:

bs authenticate -c run-upload --scopes "CREATE RUNS"

bs -c run-upload upload run \
  -n MyNovaSeqRun \
  -t NovaSeq6000 \
  /path/to/run_folder

Replace the run name, instrument type and directory with the values for your dataset. The run folder must contain the required Illumina run files, including RunParameters.xml and RunInfo.xml. A compatible SampleSheet.csv is recommended for automatic FASTQ generation where supported. Official run-upload documentation.

d. Verify the upload

After the transfer, open the project in BaseSpace and confirm that the uploaded dataset or run is visible. For FASTQ uploads, check that both R1 and R2 files are present for paired-end samples.

Important: Uploading FASTQ files adds data to a project; uploading a complete BCL run is a different workflow. Do not upload human genomic data to a public or shared project unless the appropriate permissions and data-governance requirements are satisfied.

5. Understand FASTQ files

FASTQ structure

Each read uses four lines:

Line Content
1 Header, starting with @: the read identifier (instrument, run, flowcell, lane, tile, coordinates, read number)
2 The nucleotide sequence
3 A separator, +
4 The Phred quality scores, one character per base 
@INSTRUMENT:RUN:FLOWCELL:LANE:TILE:X:Y 1:N:0:INDEX
GATTTGGGGTTCAAAGCAGTATCGATCAAATAGTAAATCCATTTGTTCAACTCACAGTTT
+
AAAFFJJJJJJFJJJJJJJJFJJJJJJJFJJJJJJJFJJJJJJJFJJJJFJJJJJJJJFJJ

This is an illustration of the format, not a read from the data.

Phred quality scores

A Phred score Q gives the probability that a base call is wrong:

Q Chance of a wrong base Accuracy
10 1 in 10 90 %
20 1 in 100 99 %
30 1 in 1,000 99.9 %
40 1 in 10,000 99.99 %

In Illumina FASTQ files each score is stored as one character (ASCII code minus 33).

R1 and R2 in paired-end sequencing

The two ends of each DNA fragment are read separately:

  • R1: the forward read.
  • R2: the reverse read of the same fragment.
  • The two files must hold the same number of reads, in the same order: read n in R1 is the mate of read n in R2. The headers match except for the read number (1: and 2:).
#| eval: false
# Optional, on a small FASTQ subset shared by the instructor
zcat sample_R1.fastq.gz | head -n 8
zcat sample_R2.fastq.gz | head -n 8
echo $(( $(zcat sample_R1.fastq.gz | wc -l) / 4 ))    # reads in R1
echo $(( $(zcat sample_R2.fastq.gz | wc -l) / 4 ))    # reads in R2 (must be equal)

6. Sequencing quality metrics

FastQC reads the FASTQ files and reports one section per metric.

Metric What it shows What is acceptable What would worry you
Per-base sequence quality Quality of each position along the reads Most positions at Q30 or above, with a slight drop at the 3’ end A drop across the whole read, or a sudden dip
Per-sequence quality scores Distribution of the mean quality per read A single peak at high quality A second peak at low quality
Adapter content Share of reads containing adapter sequence Close to zero Adapter content rising towards the 3’ end
Read length Length of the reads One length, as expected (about 100 bases for this run) Many different lengths or an unexpected value
GC content Shape of the GC distribution of reads One smooth peak A shifted or double peak, which can indicate contamination

Other FastQC modules (sequence duplication levels, per-base sequence content, overrepresented sequences) are common to flag for hybrid-capture exomes. A duplicated or unevenly composed library is not necessarily a problem: judge it in context, and remember that FastQC and the instrument’s own run metrics do not measure the same things.

Reading the read length for this run. 15.5 Gb of bases for about 77.7 million read pairs (about 155 million reads) gives about 100 bases per read. FastQC should report a length close to that.

a. Run FastQC in BaseSpace

BaseSpace offers FastQC as an app (and a FASTQ Toolkit app for trimming and filtering).

Steps:

  1. In the project, open the Apps tab and search for FastQC.
  2. Open the app and select Launch App.
  3. Give the analysis a name, for example FastQC_HCC1395BL_WES, and choose the project in which to save the results.
  4. For the input, select the sample / dataset HCC1395BL_normal_WES (SRR37849526).
  5. Check the cost estimate, then launch.
  6. Follow the status in Analyses. When it shows Complete, open it and look at the report. Each metric is given with a pass, warning or failure marker, per read (R1 and R2).

b. Decision

Situation Decision
Quality is high across most of the read, adapters are close to none, R1 and R2 have the same number of reads Acceptable: proceed to alignment
A slight drop at the 3’ end, a low level of adapter, or warnings that are typical of exomes Acceptable with a note: proceed, and write the observation down
A strong quality drop, a high adapter content, or very different R1 and R2 Investigate: trimming (FASTQ Toolkit) or a different dataset may be needed
R1 and R2 have different numbers of reads, unexpected read length, or a corrupted file Stop: the files may be incomplete; fix the import before going further

Write a short conclusion in the form: “The data are acceptable / not acceptable because …”.

A good FASTQ QC does not guarantee a good analysis. The next page checks the aligned data (mapping rate, coverage, contamination), which is the real test of whether the sample is fit for variant calling.

Key takeaways

  • A FASTQ read has four lines: identifier, sequence, separator and Phred qualities.
  • Paired-end data come in two files, R1 and R2, which must hold the same reads in the same order.
  • A Phred score of 30 means about one wrong base in 1,000.
  • FastQC reports per-base quality, per-sequence quality, adapter content, read length and GC content; MultiQC combines several reports.
  • Warnings have to be read in context: some are expected for a hybrid-capture exome.
  • The decision is explicit: acceptable, acceptable with a note, investigate, or stop.
  • Next: alignment with DRAGEN and coverage metrics.
